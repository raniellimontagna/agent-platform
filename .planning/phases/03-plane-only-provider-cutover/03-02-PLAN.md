<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Env/config -> runtime provider registry | Deployment config controls which card gateways and graphs are active. |
| BullMQ job payload -> worker | Queue payloads can be stale or missing provider fields. |
| Persisted runs -> worker/report comments | Old rows can influence provider selection during resume and continuation. |
| External webhook -> route handler | Provider webhooks cross from public Funnel/provider UI into run creation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-03-02-01 | Tampering | `env.ts` / `cards.ts` | high | mitigate | Reject active legacy primary config and only register legacy provider through explicit compatibility env. |
| T-03-02-02 | Tampering | `queue.ts` / `worker.ts` | high | mitigate | Require explicit provider/card data and throw on ambiguous state instead of inferring legacy provider. |
| T-03-02-03 | Spoofing | `/webhooks/linear` | high | mitigate | Gate legacy route by explicit compatibility config and preserve HMAC validation when enabled. |
| T-03-02-04 | Information Disclosure | env examples | medium | mitigate | Keep legacy secrets documented only as compatibility values and keep sample values, not real secrets. |
| T-03-02-SC | Tampering | package installs | high | mitigate | No package installs are planned; package/dependency deletion is explicitly forbidden by D-05. |
</threat_model>
