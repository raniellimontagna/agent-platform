<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Application writes -> database schema | Run creation and Drizzle defaults determine provider identity for new rows. |
| Legacy rows -> dashboards/docs | Operator views can misrepresent Plane vs legacy state if they prefer legacy fields. |
| Migration CLI -> external providers | `plane:migrate-linear` reads legacy source data and writes Plane provenance. |
| Local executor -> production DB | Schema validation commands must avoid destructive changes and require operator validation when local DB is unavailable. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-03-03-01 | Tampering | `runs.ts` / schema default | high | mitigate | TDD default generic card fields to Plane and keep explicit legacy branch only for legacy data. |
| T-03-03-02 | Denial of Service | Drizzle migration | high | mitigate | Use a non-destructive default-only migration and a blocking validation task before final verification. |
| T-03-03-03 | Repudiation | Grafana dashboards | medium | mitigate | Show generic card identifier and provider so operators can audit Plane rows vs legacy rows. |
| T-03-03-04 | Information Disclosure | docs/secrets | medium | mitigate | Keep secrets as sample values and document legacy Linear secrets only for migration/compatibility. |
| T-03-03-SC | Tampering | package installs | high | mitigate | No package installs are planned; do not add, remove, or upgrade dependencies in this phase. |
</threat_model>
