<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public Plane webhook -> orchestrator | Public Funnel traffic reaches only the Plane webhook path and must remain signature-validated. |
| Operator docs -> runtime exposure | Runbooks influence which routes operators expose and which secrets/env vars they configure. |
| Admin/Mission Control -> internal data | Admin pages and APIs inspect run/artifact state and require bearer-token access. |
| Worker artifacts -> operator docs | Research packs and generated assets can contain user-visible evidence and must not leak secrets. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01-01 | Spoofing/Tampering | docs/runbooks/webhook-tailscale.md | high | mitigate | Document active public exposure as /webhooks/plane only, keep HMAC verification and PLANE_WEBHOOK_SECRET as required controls, and verify against routes/webhooks.test.ts. |
| T-04-01-02 | Elevation of Privilege | docs/runbooks/mission-control.md | medium | mitigate | Keep Mission Control read-only and bearer-protected in docs; do not describe internal approval/cancel routes as public operator surfaces. |
| T-04-01-03 | Information Disclosure | research-to-landing and scheduler runbooks | medium | mitigate | Point to env/secrets owner docs instead of copying secret values or live tokens; describe public-evidence and artifact boundaries. |
| T-04-01-04 | Repudiation | docs/CURRENT.md and docs/runbooks/scheduler.md | low | accept | This plan documents existing tests and evidence locations; runtime audit logging changes are outside Phase 4 and remain covered by later refactor/verification phases. |
| T-04-01-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installs are planned; if an executor believes one is required, stop and create a blocking package legitimacy checkpoint before changing dependencies. |
